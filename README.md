# BNN Robustness Against Single Event Upsets

Research code for studying the robustness of Bayesian Neural Networks (BNNs) against
Single Event Upsets (SEUs / FP32 bitflips) — a reliability concern for ML deployed in
harsh environments such as space. Primary paper: `docs/2026_ICAART_Revalda (14).pdf`.

Two image datasets are used:

- **ShipsNet** — binary ship / no-ship classification
- **EuroSAT** — 10-class satellite imagery

Reusable code lives in `src/`, runnable entry points in `scripts/`, experiment outputs in
`results/`. See `CLAUDE.md` for the architecture notes, model/guide/SVI pattern, and
experimental variable grid.

## Environment

This project uses [`uv`](https://docs.astral.sh/uv/) for Python environment management.

```bash
uv pip install -r requirements.txt
```

GPU (CUDA 12.8) packages (torch, torchvision, torchaudio) are pinned in
`requirements.txt` and `environment.yml` but commented out in `requirements.txt` —
install them separately if needed.

## Running

```bash
# Smoke test
uv run --with pyro-ppl,torch,torchvision,tqdm,scikit-learn,python-dotenv,requests,matplotlib,pandas,numpy \
    python tests/smoke_test.py

# BNN training (ShipsNet)
uv run --with pyro-ppl,torch,torchvision,... python scripts/train_shipsnet.py

# SEU robustness evaluation
uv run --with pyro-ppl,torch,torchvision,... python scripts/eval_seu_shipsnet.py
```

Artifacts (model weights, param store, accuracy CSVs, loss CSVs, config JSON) are written
under `results/`, named `{type}_{activation}_{prior}_{timestamp}.{ext}`.

## Where results live

> **Complete inventory & progress tracker**: Consult [`result_index.md`](result_index.md) for the exact combinations matrix, directory layouts, and finished vs. pending experimental runs.

Variant suffixes are consistent throughout: `v02_00` = base, `v02_01` = smartpool,
`v02_02` = dropout, `v02_03` = weight decay.

### ShipsNet fold 1 — the paper run

Fold 1 is **not** under a `foldN/` directory. It is the original 80/20 split
(`datasplit/shipsnet_split_indices.pkl`), which the k-fold plan deliberately pinned as
fold 1 so the 252 already-trained models stayed reusable. `fold2/`…`fold5/` are the later
cross-validation additions.

| What | Path |
|---|---|
| BNN training | `results/shipsnet/bayesian/results_shipsnet_v02_{00,01,02,03}/` |
| DNN baseline (training + SEU) | `results/shipsnet/deterministic/results_shipsnet_deterministic_{00..03}[_SEU]/` |
| SEU results | `results/shipsnet/seu/results_shipsnet_v02_{00..03}_SEU/` (plus `*_SEU-median/`) |
| Best-checkpoint re-eval | `results/shipsnet/best_checkpoint_acc/` (scaffolded, currently empty) |

### ShipsNet folds 1–5 — cross-validation

Folds 1–5 cross-validation results are structured as follows:
- **BNN Training & SEU**: Complete across all 5 folds and 4 variants (`base`, `dropout`, `smartpool`, `weight_decay`) under `results/shipsnet/bayesian/fold{1..5}/` and `results/shipsnet/seu/fold{1..5}/` (21 models $\times$ 4 variants $\times$ 5 folds = 420 SEU CSVs).
- **DNN Baseline**: Models trained under `results/shipsnet/deterministic/fold{2..5}/`. Fold 1 SEU evaluations are complete in `results_shipsnet_deterministic_{00..03}_SEU/`; Folds 2–5 SEU runs are scaffolded under `results/shipsnet/seu/deterministic/`.
- **Fold CI Summary Tables**: Generated by `scripts/aggregate_seu_folds.py` in `results/tables/shipsnet_folds/`.

### `seu/` vs `seu_clean/`

Aggregate from **`seu_clean/`**. It is a deduplicated copy produced by
`scripts/dedup_seu_csvs.py`; the originals under `seu/` are never modified.

An earlier version of the eval script opened result CSVs in append mode with no per-combo
resume, so re-running a config appended a second full evaluation pass rather than skipping
finished work. The duplicates are invisible to the eval script's completeness check —
`load_completed_combos()` returns a *set* of combo keys, so a file with 336 rows covering
168 combos looks "done" — but not to `src/evaluation/aggregate.py:load_seu_results()`,
which concatenates every row. Affected configs are therefore silently double-weighted in
any mean or standard deviation over the grid.

Rows partition into passes by `initial_accuracy` (one injector construction = one baseline
MC evaluation = one value), so the script keeps exactly one whole pass per file, preferring
a pass that covers all expected combos.

Byte-comparing all 252 file pairs, `v02_00`, `v02_01` and `v02_02` are identical (63/63
each). Only three files differ, all in `v02_03`:

| File | rows in `seu/` | rows in `seu_clean/` |
|---|---|---|
| `_20260718_165400.csv` | 194 | 168 |
| `_20260718_183309.csv` | 336 | 168 |
| `_20260720_034001.csv` | 222 | 168 |

168 is the expected combo count. Both trees also carry `_archive_pre_fastsmartpool/`.

## Robustness metrics

- **AAD** (Absolute Accuracy Difference) — `|accuracy_after - accuracy_before|`
- **Softmax Difference** — mean L∞ distance of softmax outputs before/after SEU
- **ARIn** (Aggregate Robustness Index) — `sqrt((AAD² + SoftmaxDiff²) / 2)`; lower is more robust
