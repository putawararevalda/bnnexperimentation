Part B — Confidence intervals over ShipsNet folds 1–5

B.1 The trap: what counts as one observation

Do not compute the CI over injection rows. Each fold's SEU CSV contains ~336 rows, one per (layer, module, param type, bit) combination. Those rows are a deterministic, exhaustive grid, not a random sample. Taking a CI over them gives you n≈1680 across 5 folds, an interval roughly ±0.002 wide, and it would be measuring how much ARIn varies between injection sites — which is enormous and completely uninteresting. It says nothing about training-run variability, which is precisely what R1 asked for.

A reviewer who spots this will read it as statistical window-dressing, which is worse than reporting no CI at all.

The unit of analysis is the fold. One fold = one independent training run = one observation. n = 5. That is what the reviewer's objection is about: "model performance can vary substantially depending on the initial training conditions, random seed, or stochastic optimization path."

B.2 The procedure

Step 1 — collapse each fold to one number. For a given cell (say, activation = WG), average ARIn over the fixed injection grid within fold k:

x̄k = (1/M) Σj=1..M ARInk,j     k = 1…5

The grid must be identical across folds (same M, same combinations) or the fold means are not comparable. Assert this in code, don't assume it.

Step 2 — Student-t interval over the 5 fold means. With n = 5, the normal approximation is not usable; use the t distribution with 4 degrees of freedom.

x̄ = (1/n) Σ x̄k     s = √[ Σ(x̄k − x̄)² / (n−1) ]

CI95% = x̄ ± t0.975, 4 · s / √n     where t0.975, 4 = 2.776

Note 2.776 vs 1.96 — with five folds the interval is 42% wider than a naive normal interval. Using 1.96 here is a common and easily-caught error.

The two marginal intervals overlap — [0.0386, 0.0514] vs [0.0473, 0.0603]. Read naively, that says "no significant difference between BNN and DNN", and you would have handed R1 the paper's conclusion on a plate.

The paired interval on the per-fold difference does not contain zero — [0.0086, 0.0090]. The BNN is more robust, consistently, on every single fold. The marginal CIs are wide because folds differ in difficulty, and that fold effect is shared by both models, so it cancels in the difference.

Report the paired difference. It is the correct analysis (all models see the same 5 splits — this is a matched design, not two independent samples), it is far more powerful at n=5, and it directly answers "are the reported differences genuine or artifacts of a single run?"

B.4 Implementation

src/evaluation/aggregate.py already anticipates a fold column (see n_folds in aggregate_across_folds), but the SEU CSVs do not currently carry one — it has to be attached at load time from the directory path. It also computes std only; the CI half-width and the paired path need adding.

"""Fold-level confidence intervals for SEU robustness metrics."""
import re
import numpy as np
import pandas as pd
from scipy import stats

from src.evaluation.aggregate import load_seu_results, add_robustness_metrics

FOLD_RE = re.compile(r"fold(\d+)")


def attach_fold(df: pd.DataFrame) -> pd.DataFrame:
    """Derive the fold index from source_file; fold 1 is the top-level split."""
    out = df.copy()
    out["fold"] = (
        out["source_file"].str.extract(FOLD_RE, expand=False)
        .fillna("1").astype(int)
    )
    return out


def fold_means(df: pd.DataFrame, group_cols: list[str],
               metric: str = "arin") -> pd.DataFrame:
    """Collapse each (group, fold) to a single mean over the injection grid.

    Raises:
        ValueError: If the injection grid differs across folds, which would
            make the fold means incomparable.
    """
    valid = df[df[metric].notna()]
    counts = valid.groupby(group_cols + ["fold"]).size()
    if counts.groupby(level=list(range(len(group_cols)))).nunique().gt(1).any():
        raise ValueError("injection grid differs across folds; cannot compare")
    return valid.groupby(group_cols + ["fold"])[metric].mean().reset_index()


def ci_from_folds(values: np.ndarray, alpha: float = 0.05) -> dict:
    """Student-t CI treating each fold as one independent observation."""
    n = len(values)
    if n < 2:
        raise ValueError(f"need >= 2 folds, got {n}")
    mean = float(values.mean())
    sem = float(values.std(ddof=1) / np.sqrt(n))
    t_crit = float(stats.t.ppf(1 - alpha / 2, df=n - 1))
    half = t_crit * sem
    return {"mean": mean, "sd": float(values.std(ddof=1)), "sem": sem,
            "t_crit": t_crit, "ci_low": mean - half, "ci_high": mean + half,
            "half_width": half, "n_folds": n}


def paired_ci(a: pd.DataFrame, b: pd.DataFrame,
              metric: str = "arin", alpha: float = 0.05) -> dict:
    """CI on the per-fold difference b - a. Folds must align one-to-one.

    Use this for any two-condition claim (BNN vs DNN, WG vs ReLU): the fold
    effect is shared and cancels, which matters enormously at n=5.
    """
    merged = a.merge(b, on="fold", suffixes=("_a", "_b"))
    if len(merged) != len(a) or len(merged) != len(b):
        raise ValueError("folds do not align one-to-one between conditions")
    diff = (merged[f"{metric}_b"] - merged[f"{metric}_a"]).to_numpy()
    out = ci_from_folds(diff, alpha)
    out["significant"] = bool(out["ci_low"] > 0 or out["ci_high"] < 0)
    return out


if __name__ == "__main__":
    df = load_seu_results("results/shipsnet/seu")
    df = df[~df["source_file"].str.contains("_archive")]
    df = add_robustness_metrics(attach_fold(df))

    per_fold = fold_means(df, ["variant", "activation_fn", "prior"])
    rows = []
    for keys, g in per_fold.groupby(["variant", "activation_fn", "prior"]):
        rows.append({**dict(zip(["variant", "activation_fn", "prior"], keys)),
                     **ci_from_folds(g["arin"].to_numpy())})
    print(pd.DataFrame(rows).round(4).to_string(index=False))

B.5 How to report it in the paper

In the table. One column, not three. 0.0450 [0.0386, 0.0514] is more informative than 0.0450 ± 0.0051 and takes the same width. Do not print mean, SD, SEM and CI — that is four numbers saying one thing, and it costs column width you do not have.

In the caption. The caption must state the unit of analysis or the CI is uninterpretable. Something like:

"Values are means over 5-fold cross-validation with 95% confidence intervals (Student-t, 4 d.f.). Each fold contributes one observation, obtained by averaging the metric over all M = 336 injection sites for that fold; intervals therefore reflect variability across independent training runs, not across injection sites."

For the BNN-vs-DNN claim. Report the paired difference with its CI in the text, e.g. "the BNN reduces ARIn by 0.0088 (95% CI [0.0086, 0.0090]), consistently across all five folds". This is the single sentence that answers R1's central methodological objection, and it costs one line.

If you have room for a figure. A forest plot — one row per design choice, point = fold mean, whiskers = 95% CI, vertical reference line at the baseline — communicates all of this in a single column and replaces a table entirely. Only do this if the heatmap swap above leaves you the space.

B.6 Two caveats to state, not hide

k = 5, not the k = 10 R1 suggested. Say so explicitly and justify it on compute cost (252 trained models per fold × the SEU grid). A stated, costed deviation reads as engineering judgement; an unexplained one reads as cutting corners.

Fold 1 is the original 80/20 split. It was pinned as fold 1 so the existing 252 models stayed reusable — which means fold 1 is not drawn from the same k-fold partition scheme as folds 2–5, and its test set may overlap other folds' training data. Either state this in the methodology, or exclude fold 1 and run a genuine fold and use n = 5 clean folds. The first is cheaper; the second is safer if a reviewer looks closely.

The MC noise floor. Per docs/analysis/seu_metric_noise_floor.md, roughly half the BNN softmax-difference signal is Monte-Carlo sampling noise, and the DNN softmax difference is affected by a double-softmax bug. A CI that is narrower than the noise floor is not evidence of anything. Fix the DNN metric before quoting any BNN-vs-DNN interval — otherwise the paired CI above will be precise and wrong.

Summary of recommendations

  1. EuroSAT lead finding is the activation function, not the model variant. WG dominates ReLU on both robustness (−46% ARIn) and accuracy (+7 pts). The variant grid is a null result — one sentence.
  2. Bit 1 dominates every other factor by 6.5×. Promote it to the abstract; it motivates targeted exponent protection as future work, which also fixes R1's "conclusions/future work not convincing".
  3. Fold Tables 3–5 into one heatmap figure. Fixes the overflow complaint and pays for the EuroSAT content.
  4. One combined two-dataset table, not two parallel tables.
  5. CI unit of analysis is the fold (n = 5, t = 2.776), never the injection row.
  6. Report paired per-fold differences for any two-condition claim — marginal CIs will overlap and understate your result.
  7. Fix the DNN softmax-difference bug first. Everything above is downstream of that metric being correct.
